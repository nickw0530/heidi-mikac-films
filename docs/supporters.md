# Supporter wall operations

The `/merch` credits combine confirmed website merchandise, Crowdfundr CSV imports and manual offline/alternative payments. Merchandise is credited as support, not a charitable donation. The gross merchandise subtotal excludes shipping. Public responses contain only a permitted display name, permitted USD amount and currency. Contact email is used only as an internal identity digest; addresses, messages, email and transaction identifiers are never public.

The wall checks for changes every five seconds while the page is visible and refreshes after website checkout. It offers Pause credits and a static, scrollable reduced-motion view. Crowdfundr is **CSV-imported, not a connected live feed**.

## Administrator workflow

1. Sign in through the existing secured member portal and open merchandise/supporter management. Ordinary member accounts cannot read or change supporter records.
2. Export Crowdfundr's all-time **Transactions report (csv)**. Preview the file, inspect status, gross support and both privacy preferences, then confirm. Preview does not save data. A changed ledger requires another preview before saving.
3. Re-import subsequent all-time reports. Each provider transaction ID remains a separate payment record; repeated imports update that record without creating another payment. Exact processor references also prevent counting the same payment across website, import and manual channels. Provider IDs are case-sensitive opaque values. Conflicting statuses/privacy for the same reference fail closed.
4. Use the manual form for cash, Venmo, bank transfer or another payment received outside these records. Keep one record per payment. Record the actual reference and provider when available. Add a verified email or choose “Verified same supporter as” only after confirming identity; equal names alone never merge people. Blank identity fields on edits retain the previous match.
5. Obtain separate permission for a public name and amount. Missing/private names appear as Anonymous. A private amount is not disclosed. Private-name payments remain separate from named credits. Hide/Show controls visibility without granting missing consent. Use duplicate review only for two records of the **same payment**, never for a repeat contribution.
6. Pending, failed, refunded, hidden and duplicate records do not count. Manual partial refunds require the confirmed refund amount; only the remainder counts. A CSV partial refund has no confirmed refund amount and stays excluded. Re-importing an older paid CSV cannot reverse a recorded refund. Full refunds remain excluded. Keep partial Crowdfundr payments excluded until their reconciliation can be verified; do not create an additional compensating payment that could double count.

The CSV accepts up to 5,000 rows and 2 MB per import, requires USD and the exported privacy/status columns, and rejects ambiguous duplicate IDs or malformed input before saving. Gross contribution uses `Contribution amount`, not total charged, recovered fees or net proceeds. Moderation survives subsequent CSV imports.

## Supported Crowdfundr integration and activation blockers

Crowdfundr identifies ConnectionPoint as its platform provider, and its support link leads to the shared [ConnectionPoint Help Centre](https://connectionpoint.com/help/). The official [ConnectionPoint API reference](https://api-reference.connectionpoint.com/) documents REST payment access and `payment.created` / `payment.updated` webhooks.

Automatic synchronization is not activated by this implementation. Activation requires an approved client application at [ConnectionPoint Apps](https://connectionpoint.com/apps), campaign-manager OAuth authorization, the campaign ID and a registered campaign webhook endpoint with its secret securely stored. Webhook verification uses HMAC-SHA512 over the timestamp plus raw body. Payment statuses include completed, preapproved, cancelled, refunded and reversed. Payment responses expose private payer information; the published response schema does not document the CSV's show-name/show-amount flags or a partial-refund amount. Confirm actual privacy/refund payloads and access before implementing a public feed. Do not infer public consent from an API-returned payer name or email, or advertise true real-time delivery before end-to-end verification. See the reference's [authentication](https://api-reference.connectionpoint.com/#section/Authentication-and-Authorization), [payments](https://api-reference.connectionpoint.com/#tag/Payments) and [webhooks](https://api-reference.connectionpoint.com/#tag/Webhooks) sections.

Website/admin writes use the existing strongly consistent Netlify ledger with revision checks. Imported/manual support never changes stock or invents a merchandise sale. Website PayPal status reconciliation remains available through the existing administrator payment-check action; this change does not add a PayPal or Crowdfundr webhook subscription.
