# Supporter wall operations

The homepage's **Lifetime supporters** credits combine paid website merchandise, eligible past and current Crowdfundr public contributions, and manual offline/alternative payments. The compact **Current campaign supporters** credits near the top of `/merch` include Crowdfundr campaigns marked current and eligible manual payments explicitly assigned to one of those campaigns. Unassigned manual payments, manual payments assigned to historic campaigns, and merchandise belong in lifetime recognition. CSV recognition remains available when automatic public mode is off; legacy CSV/API records without a campaign ID belong to the original Take Two campaign. Merchandise is support, not a charitable donation; its gross subtotal excludes shipping. Each public credit contains only a permitted display name, permitted USD amount and currency. The endpoint also supplies a separate, whitelisted campaign ID/title/current-state list. Contact emails, addresses, messages, internal identity digests and transaction references are never public.

Each wall checks for changes every five seconds while its page is visible and refreshes after website checkout. Both offer Pause credits and a static, scrollable reduced-motion view. Crowdfundr public mode checks each configured campaign's complete native public feed about every two minutes. Future public online credits update without new CSV imports. This is a public recognition mirror, not guaranteed real-time payment reconciliation. Current-campaign amounts are a subset of lifetime support: do not add the two views together as separate funds raised.

## Administrator workflow

1. Sign in through the existing secured member portal and open merchandise/supporter management. Ordinary member accounts cannot read or change supporter records.
2. If using CSV recognition, export Crowdfundr's all-time **Transactions report (csv)**. Preview the file, inspect status, gross support and both privacy preferences, then confirm. Preview does not save data. A changed ledger requires another preview before saving. Public mode retains these private audit records but replaces their wall recognition, so they are not counted twice.
3. Re-import subsequent all-time reports. Each provider transaction ID remains a separate payment record; repeated imports update that record without creating another payment. Exact processor references also prevent counting the same payment across website, import and manual channels. Provider IDs are case-sensitive opaque values. Conflicting statuses/privacy for the same reference fail closed.
4. Use the manual form for cash, Venmo, bank transfer or another payment received outside these records. Keep one record per payment. Record the actual reference and provider when available. Matching public names combine automatically across channels, ignoring case and repeated whitespace, unless different verified profiles from the same provider conflict. Add a verified email or choose “Verified same supporter as” after confirming identity to connect changed names or resolve ambiguous matches. For existing Crowdfundr or website records, use **Review supporter / duplicate → Verified same supporter as → Save supporter review**. This links recognition without marking separate payments as duplicates or changing any amount, privacy choice or hidden payment. Links survive automatic campaign refreshes. Blank identity fields on manual edits retain the previous match; the review form can explicitly clear a saved match.
   In the manual form, use **Campaign** to assign the payment. Choose a **Current** campaign to include that same payment in both lifetime and current-campaign recognition. **Historic** campaigns and **Lifetime support only** appear in lifetime recognition. Editing an existing record loads its saved campaign; choosing **Lifetime support only** clears that assignment. Leaving the selector unchanged preserves the saved assignment, including a change another administrator made while the form was open. An unavailable saved campaign stays lifetime only until reassigned. The ledger shows the campaign choice beside the source/date. Campaign assignment never creates a second payment or changes financial, privacy, duplicate or hidden settings.
   Use **Delete manual record** to remove an accidental manual entry from the active ledger and totals. The private record remains recoverable under **Deleted manual records → Restore manual record**, with its prior privacy and visibility settings retained.
5. Website checkout offers only a public-name choice, with Anonymous when a name is withheld. Anonymous credits show verified support amounts, including amounts retained in older website, manual and CSV records, regardless of their old amount-display flag. Original flags remain in the private audit records. Named credits retain their existing amount preferences; a private amount in a named cumulative group withholds that group's total. Anonymous payments stay separate from named credits and never disclose the original name or private identity. Hide/Show does not change names or financial status. Use duplicate review only for two records of the **same payment**, never for a repeat contribution.
6. Pending, failed, refunded, hidden and duplicate records do not count. Manual partial refunds require the confirmed refund amount; only the remainder counts. A CSV partial refund has no confirmed refund amount and stays excluded. Re-importing an older paid CSV cannot reverse a recorded refund. Full refunds remain excluded. Keep partial Crowdfundr payments excluded until their reconciliation can be verified; do not create an additional compensating payment that could double count.

The CSV accepts up to 5,000 rows and 2 MB per import, requires USD and the exported privacy/status columns, and rejects ambiguous duplicate IDs or malformed input before saving. Gross contribution uses `Contribution amount`, not total charged, recovered fees or net proceeds. Moderation survives subsequent CSV imports.

Show/Hide and duplicate review check the selected payment's revision, so automatic campaign checks do not invalidate an open control. A concurrent change to that payment still requires refreshing and reviewing it. Visibility success or failure appears beside the row button; showing a payment does not override its privacy, status or duplicate exclusions.

## Automatic public credits

In the administrator portal, open **Website → Supporter wall → Crowdfundr automatic connection**. The campaign controls list all campaigns included in lifetime history; mark any running campaigns current to include them together on `/merch`. Add a future campaign using its exact public ID and title, then save. Campaign settings require the current settings revision. **Check public credits now** performs an immediate refresh; **Use CSV credits instead** turns public mode off and restores recognition from saved CSV records. **Enable automatic public credits** verifies complete public snapshots before first activation. Review each campaign's status rather than assuming every historical source succeeded because the current campaign is connected.

The confirmed initial registry contains Take Two (`e2ozh2`, current), Double Feature Fundraiser (`b2mXyf`), the organization Wherein Lies Continue campaign (`62gpI9`), and the older personal Wherein Lies Continue campaign (`f2jVO7`). All ten public records in the latter are preapprovals and are excluded. Heidi's [campaign update](https://crowdfundr.com/stories/0NKvvc) says its goal was not reached and funds would be returned. Do not count those pledges, or infer replacement Venmo/Cash App payments without their separate verified records.

Public mode needs no Crowdfundr login, API approval, password or secret. It makes anonymous requests to the same [native public contribution feed](https://crowdfundr.com/api/campaigns/e2ozh2/donations?v=1&max-results=25) used by the [public campaign page](https://crowdfundr.com/e2ozh2). Each entry must have current, explicit `isAnonymous`, `showAmount`, `deleted`, `isPreapproval` and `offline` booleans, a matching campaign/currency and a stable public activity ID. Anonymous entries never publish an owner name. Crowdfundr omits the actual amount when its amount-display flag is off; the ledger's zero placeholder is not a verified $0 contribution. Deleted, preapproved and offline entries are excluded; record offline support separately in admin.

For an anonymous Crowdfundr record whose amount is withheld from the public feed, use **Review supporter / duplicate → Verified anonymous contribution amount ($)**. Copy the actual contribution amount from the campaign owner's transactions report and match its **View public post** activity ID exactly to the ledger reference. Do not use fees, total charged, net proceeds, date-only guesses or invented amounts. Saving this verification changes recognition only, leaves the original public snapshot and flags intact, and survives automatic refreshes. A fresh amount supplied by Crowdfundr takes precedence. If the source later exposes a name while keeping its amount private, the anonymous verification is no longer publicly applied. Clear the field to remove a verification. A missing amount remains unknown until verified; public polling cannot retrieve values Crowdfundr omits. No new customer amount choice or amount notice is added.

Stable public activity IDs prevent repeat snapshots from creating duplicate credits. Verified identities combine repeat contributions even after a public name changes. Matching public names also connect manual, website and campaign credits when verified profiles do not conflict. Only visible, eligible payments participate in name matching; anonymous payments stay separate and show their verified amounts. Named private amounts still withhold a named cumulative total. Each payment remains separate in the audit ledger. All Crowdfundr CSV/API recognition is replaced by the complete public projection while this mode is on. Use duplicate review only for two records of the same payment.

The scheduled function refreshes about every two minutes, with complete pagination and a 500-entry limit per campaign. Only a fully verified campaign snapshot replaces its previous records. A failing historical source does not discard other fresh campaigns; its records are withheld after five minutes without a successful check, with no fallback to old CSV permissions. Removed activities disappear on the next successful source check. Source failures and partial connectivity appear in the portal. Original Take Two activity IDs and all existing moderation/manual transactions survive this migration; new campaigns namespace their activity IDs. The source is an undocumented public website endpoint and its contract may change.

This feed does **not** confirm bank settlement, chargebacks, full refunds or partial-refund accounting. A contribution still present publicly may continue to appear here; use **Hide payment** for a known refunded contribution that remains in Crowdfundr's activity. Do not represent public-feed status as processor-confirmed payment status. Crowdfundr's own [donation-feed description](https://fundrazr.com/pages/how-it-works) explains its public recognition, and supporters may [change existing contribution privacy](https://connectionpoint.com/help/docs/can-my-contribution-be-completely-anonymous/).

## Advanced transaction API connection

1. In [ConnectionPoint Apps](https://connectionpoint.com/apps), register the website integration with this exact redirect URL: `https://heidimikacfilms.com/.netlify/functions/crowdfundr-callback`. Registration requires review. An app marked **Unvetted** is awaiting review; the registration screen states that ConnectionPoint will review the client registration.
2. In **Crowdfundr automatic connection**, expand **Advanced: transaction API connection** and save the approved app's **Client ID**. This setup uses OAuth PKCE and requests only `read_only` access. It does not require a client secret or Crowdfundr password. Authorization credentials remain on the server.
3. Select **Authorize read-only access**, sign in as the campaign manager through ConnectionPoint and return to the fixed website callback. Select **Sync now**, then inspect the connection status and last completed synchronization. Saving a Client ID alone does not authorize API access.
4. Distinguish **credentials connected** from **automatic API publication active**. Authorization validates access to the configured USD retake campaign; API publication activates only after payment privacy is verified. A connected credential with unverified privacy is not an active API feed. Public mode takes precedence over API/CSV recognition. Use **Disconnect locally** to remove stored API authorization; this does not revoke the provider-side app grant or disable separately enabled public mode.

The scheduled function attempts a full paginated reconciliation about every two minutes, including old payments so refunds are not missed by checking only new IDs. Each run supports at most 500 payments. A larger report pauses automatic publication for administrator review rather than applying an incomplete ledger. Verified changes appear on the public wall on its next five-second refresh. The schedule and API response time are separate from this wall refresh; do not describe them as instant delivery.

Each API payment must match the configured campaign and USD currency, include stable payment/transaction references, and supply **explicit boolean `show_name` and `show_amount` fields**. Missing fields never imply consent. If an initial probe lacks them, automatic publication stays inactive and existing CSV credits remain unchanged. If previously API-managed records later lose current privacy fields, those records are withheld rather than reusing older consent. The portal reports this privacy blocker without exposing tokens, donor data or raw provider errors.

The official [ConnectionPoint API reference](https://api-reference.connectionpoint.com/) documents read-only OAuth PKCE, payments and signed webhooks. Its published Payment schema does not document those two privacy flags or a partial-refund amount, so successful authorization alone cannot establish safe public synchronization. Current authenticated responses must satisfy the explicit field checks. This matters because supporters can [change the visibility of an existing contribution](https://connectionpoint.com/help/docs/can-my-contribution-be-completely-anonymous/). Partial refunds without a confirmed refund amount remain excluded. No Crowdfundr webhook subscription is created by this implementation; it uses scheduled API reconciliation.

The current advanced app registration remains Unvetted; API campaign authorization has not been verified as active. This does not block the independent public-feed mode. Website/admin writes use the existing strongly consistent Netlify ledger with revision checks. Imported/manual support never changes stock or invents a merchandise sale. Website PayPal status reconciliation remains available through the existing administrator payment-check action; this change does not add a PayPal webhook subscription. Deployment and live activation must be verified separately before reporting automatic Crowdfundr updates as active.
